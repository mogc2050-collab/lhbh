# ممالك الحياة | Medieval Life

**لعبة استراتيجية اقتصادية وحياة يومية باللغة العربية، تعمل على Android بدون اتصال بالإنترنت أثناء اللعب.**

> هذه نسخة لعب أصلية قابلة للتطوير برسومات إيزومترية ثنائية الأبعاد مرسومة برمجيًا باستخدام Flutter CustomPainter. ليست لعبة ثلاثية الأبعاد، وليست مطابقة بالبكسل للصور التصورية الموجودة داخل `design_reference/`. تلك الصور مراجع فنية للمراحل المستقبلية، وليست شاشات مزيفة لواجهة التطبيق.

## ما الذي يعمل فعلًا؟

- خريطة قرية إيزومترية قابلة للسحب والتكبير، مع تحديد المواقع وتحريك البطل عبر مسارات تتجنب المباني (BFS).
- بناء **11 نوعًا من المباني** وترقية المباني إلى المستوى الخامس، ونظام سكان/عمال وسعة مخازن.
- بناء منازل و**بيع العقارات** مقابل ذهب حقيقي داخل اقتصاد اللعبة، بما في ذلك خصم إنتاج المباني المباعة.
- سوق يعمل دون اتصال: شراء وبيع 9 أنواع موارد، أسعار متغيرة، فارق سعر بين البيع والشراء، سيولة ومخزون محدودان للتاجر، وسجل معاملات.
- سلاسل إنتاج تلقائي حسب الوقت والعمال والمواد: حطب، محجر، قمح، منشرة ألواح، مخبز، مصنع طوب، ورشة، وبئر.
- احتياجات البطل: الجوع، العطش، الطاقة، الصحة، المزاج، والنظافة؛ الأكل والشرب والنوم والاغتسال والعمل اليدوي والتصنيع.
- تعاقب الليل والنهار والفصول، إيجارات منازل وأجور عمال كل يوم، مهام ومكافآت وخبرة ومستويات.
- أيقونة تطبيق أصلية وهوية عربية في Android.
- حفظ تلقائي كل 15 ثانية وعند مغادرة التطبيق، واستعادة عند التشغيل من التخزين المحلي باستخدام `shared_preferences`.
- أزرار إيقاف/تشغيل وتسريع الوقت ×1 و×2 و×4، دعم كامل للغة العربية واتجاه RTL.
- **لا توجد خوادم، ولا تسجيل دخول، ولا إعلانات، ولا مشتريات حقيقية، ولا اتصال إنترنت أثناء اللعب.**

## طريقة الحصول على APK بدون تثبيت Flutter على جهازك

1. فك ضغط ملف ZIP الذي استلمته على الكمبيوتر أو الهاتف.
2. أنشئ مستودعًا جديدًا في https://github.com/new ويفضل أن يكون `Private` إن أردت حماية الكود.
3. ارفع **محتويات** مجلد `medieval_life` إلى جذر المستودع، وليس ملف ZIP نفسه. يجب أن يكون `pubspec.yaml` مباشرة في الجذر، بجواره `lib/` و`test/`.
4. مهم جدًا: تأكد من وجود المسار **`.github/workflows/build-apk.yml`** داخل المستودع. إذا لم يرفعه المتصفح، افتح **Add file → Create new file** واكتب الاسم كاملًا `.github/workflows/build-apk.yml`، ثم انسخ محتوى الملف من نسخة ZIP واعمل Commit.
5. افتح **Actions** ← **Build Android APK - Manual Only** ← **Run workflow** ← **Run workflow**.
6. انتظر اكتمال العملية وظهور علامة النجاح، ثم افتح تشغيلها ومن قسم **Artifacts** حمّل `Mamlakat-Al-Hayat-Android-APK`، وفك ضغطه لتجد `app-release.apk`.
7. افتح ملف APK على جهاز Android واسمح بالتثبيت من مصدر خارجي إذا طلب الهاتف ذلك.

### ضمان أن البناء يدوي فقط

ملف `.github/workflows/build-apk.yml` يحتوي على trigger واحد فقط: `workflow_dispatch`، ولا يحتوي على `push` أو `pull_request` أو `schedule`، ولذلك **رفع الملفات أو تعديلها لا يبدأ البناء تلقائيًا**. يسمح GitHub بالتشغيل اليدوي وفق صلاحيات الأشخاص داخل المستودع. يجب أن يكون ملف workflow موجودًا على الفرع الافتراضي حتى يظهر زر التشغيل اليدوي.

### لماذا لا يوجد مجلد android/ داخل الأرشيف؟

لأن GitHub Actions يقوم بإنشاء ملفات Android المتوافقة مع نسخة Flutter المستقرة وقت تشغيل البناء باستخدام:

```sh
flutter create --platforms=android --project-name=medieval_life --org=com.mamlakatlife .
```

ويطبّق أيقونة اللعبة واسمها العربي باستخدام `scripts/customize_android.py`، ثم ينفّذ `flutter pub get` واختبارات `flutter test` وأخيرًا `flutter build apk --release`. بهذه الطريقة لن تضطر إلى تثبيت أدوات على كمبيوتر الشركة. **لا تحذف خطوة `flutter create` من workflow.**

### ملاحظة عن توقيع تحديثات Android

هذا البناء معد للتجربة والتثبيت الشخصي. قد يستخدم إعداد التوقيع الافتراضي للمشروع المولد، والذي لا يضمن مفتاحًا ثابتًا بين عمليات بناء GitHub المختلفة. **للتوزيع الرسمي والتحديثات من دون حذف التطبيق يجب إعداد مفتاح توقيع خاص وثابت وحفظه بأمان في GitHub Secrets**؛ لا تضع المفتاح الخاص داخل مستودع عام. كما أن نسخة Google Play تتطلب عادة إعداد `AAB` وتوقيعًا مناسبًا.

## طريقة اللعب

- حرّك الخريطة بالسحب، وقرّب/بعّد بإصبعين.
- المس أرضًا فارغة ليتحرك البطل إليها؛ المس مبنى لتفتح ترقيته أو بيعه.
- من **البناء** اختر المبنى، ثم المس مكانًا فارغًا على أرض القرية. تُخصم الموارد عند البناء.
- من **السوق** اختر موردًا وعدد الوحدات، ثم زر الشراء أو البيع. التاجر له مخزون وذهب محدودان.
- المواد الخام تتحول لمنتجات أخرى تلقائيًا كل نصف ساعة داخل اللعبة وفق المباني والعمال والمواد المتوفرة.
- احتفظ بطعام وماء للبطل، واسترح عندما تهبط طاقته. سيؤثر الإهمال على صحته.
- راقب **دفتر الاقتصاد** لتعرف الإيجارات والأجور وعمليات البيع والشراء.

## بنية الملفات

```text
.github/workflows/build-apk.yml    # البناء اليدوي فقط
lib/main.dart                       # نقطة تشغيل Flutter
lib/game/catalog.dart               # الموارد والمباني والتكاليف
lib/game/game_state.dart            # الاقتصاد والحياة والحفظ والحركة
lib/ui/game_theme.dart              # المكونات والألوان
lib/ui/world_painter.dart           # الرسوم الإيزومترية الحقيقية
lib/ui/game_screen.dart             # كل شاشات اللعب
pubspec.yaml                        # تبعيات Flutter
test/                               # اختبارات الاقتصاد والواجهة
design_reference/                   # الصور التصورية (غير مستخدمة في تشغيل اللعبة)
```

## حدّ النسخة الحالية

الموجود مشروع لعبة **قابل للعب بمميزات اقتصادية أساسية مترابطة** وليس محاكاة تاريخية ضخمة ثلاثية الأبعاد. لا يشمل جيوشًا، حصارات، ذكاء اصطناعي للسكان، نظام عائلات، أرضًا مفتوحة بلا حدود، أصواتًا مخصصة أو رسومًا ثلاثية الأبعاد مطابقة للصور. يمكن تطوير هذه الأمور على مراحل مع الحفاظ على ملفات المحرك وقاعدة البيانات المحلية.

## اختبارات وتحقق

يمكن تشغيل الاختبارات على GitHub عند الضغط اليدوي على Workflow. في بيئة إعداد هذا الأرشيف لم يكن Flutter SDK متاحًا لذلك **لم يتم بناء APK أو تنفيذ اختبارات Flutter هنا**، والنتيجة الفعلية للبناء تُعرف عند تشغيل Actions لأول مرة. تمت مراجعة تراكيب الملفات والإعدادات آليًا قبل تسليم الأرشيف.
